Architectural Overview

An analytical window function engine implementing LAG()-based clickstream sessionization, ROW_NUMBER() date-difference islands for consecutive activity streaks, and ROWS vs RANGE sliding window frames.

In production relational and analytical database systems—spanning PostgreSQL, SQLite, MySQL/InnoDB, and DuckDB—understanding how query clauses, schema constraints, index structures, and storage engines execute under the hood separates surface-level query authors from staff-level database engineers. This capstone build lab guides you through implementing Clickstream Sessionizer, Streak Tracker & Rolling Window Analyzer from first principles with deterministic self-test invariants.

Guided Implementation Walkthrough (4 Progressive Steps)

Step 1: Clickstream Sessionization via LAG() & Cumulative Sum

  • Core Database Concept: Two-Stage Window Pipeline: Inactivity Flagging + Running Session Counter
  • Target Module: index.js (WindowAnalyticsEngine.sessionizeEvents)
  • Engineering Specification: Implement sessionizeEvents(events, timeoutSec) to partition events by user_id, order by tsSec, compute LAG(tsSec), flag new sessions whenever tsSec - prevTs > timeoutSec, and assign a running session_id via cumulative sum.
  • Implementation Hint: Sort by user_id, tsSec; mark isNewSession = (prevTs === null || tsSec - prevTs > timeoutSec ? 1 : 0), then accumulate session_num.
  • Verification Invariant: deterministic assertion verified in test.js step 1

Step 2: Gaps-and-Islands Consecutive Day Streak Finder

  • Core Database Concept: Constant Difference Invariant: dayIndex - ROW_NUMBER() OVER (PARTITION BY user ORDER BY dayIndex)
  • Target Module: index.js (WindowAnalyticsEngine.computeStreaks)
  • Engineering Specification: Implement computeStreaks(activityDays) using the classic Gaps-and-Islands invariant: subtracting sequential ROW_NUMBER() from integer dayIndex yields a constant islandKey across consecutive days.
  • Implementation Hint: Deduplicate (user_id, dayIndex), sort ascending, group by islandKey = dayIndex - rowNumber, and return streak start, end, and length.
  • Verification Invariant: deterministic assertion verified in test.js step 2

Step 3: Physical ROWS Window Frame Moving Average

  • Core Database Concept: Evaluating ROWS BETWEEN k PRECEDING AND CURRENT ROW
  • Target Module: index.js (WindowAnalyticsEngine.movingAvgRows)
  • Engineering Specification: Implement movingAvgRows(rows, metricCol, precedingRows) to compute the physical row-count sliding window average.
  • Implementation Hint: For index i, slice rows from Math.max(0, i - precedingRows) to i + 1 and average the metric.
  • Verification Invariant: deterministic assertion verified in test.js step 3

Step 4: Logical RANGE Window Frame Sum with Peer Ties

  • Core Database Concept: Evaluating RANGE BETWEEN delta PRECEDING AND CURRENT ROW Including All Peer Ties
  • Target Module: index.js (WindowAnalyticsEngine.movingSumRange)
  • Engineering Specification: Implement movingSumRange(rows, orderCol, metricCol, delta) to sum all tuples whose orderCol falls within [curOrder - delta, curOrder], including all duplicate peer timestamps.
  • Implementation Hint: Include all rows j where rows[j].orderVal >= rows[i].orderVal - delta && rows[j].orderVal <= rows[i].orderVal.
  • Verification Invariant: deterministic assertion verified in test.js step 4
